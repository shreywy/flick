Flick

2026 · Windows · Electron, React, TypeScript · Open source

A desktop app for the films and shows on my own drive. It sorts new downloads into place, pulls artwork from TMDB, and plays nearly any file with seeking that lands on the exact second. You open it, watch something, close it.

Why I made it

I keep films and shows in a folder on a second drive. Kodi played them, but I never got on with it, and Plex wants a server running in the background. I wanted the streaming-app experience, artwork and Continue watching and a decent player, as a program I open and close.

So Flick is that. It's built around my setup, a 3440×1440 ultrawide and a library that grows by downloads landing in one folder, but nothing in it is specific to my machine.

Cards turn into the player

Clicking a thumbnail flies it to the middle of the screen and opens the player out of it. Going back runs the same flight in reverse and drops it into its slot in the row. Play buttons grow straight out to the edges instead, because a button has no picture to fly.

It's the browser's View Transitions API, so what you see underneath is the real page. Scroll or click while it's moving and it finishes early and gets out of the way.

The library looks after itself

Flick reads a Movies and a TV Shows folder. Posters, backdrops, title logos, cast and episode stills come from TMDB and get written into each title's folder, so they're fetched once and other players can use them too.

Anything that lands in the downloads folder is renamed, moved into the right place, and given artwork and an English subtitle the next time Flick opens. Files that are still being written are left alone until they stop changing. If a name can't be read, it waits in Settings with a Fix match button rather than being guessed at.

A player that takes whatever you give it

MP4s with AAC audio play as they are. Anything else, an MKV with DTS or TrueHD, 5.1 Opus, a 4K HEVC remux, goes through ffmpeg: the video is copied untouched and only the audio is converted. Styled anime subtitles render through libass, the same library mpv uses, so signs and karaoke come out the way they were made.

Subtitle size is set by the pixel, and the font, colours, background, outline, shadow, height and delay can all be changed while the film plays. If a file has none, Flick searches OpenSubtitles or SubDL for that file without leaving the player.

Skip intro, found by listening

Most of my episodes don't have chapter markers, so Flick works the intro out from the audio. It fingerprints the first six minutes of an episode and of the episodes either side with Chromaprint, then slides the fingerprints past each other looking for the longest stretch that matches.

An intro only counts when both neighbours agree on it. Otherwise a "previously on" recap, which contains last week's episode, would match last week and be taken for the intro. Credits work the same way from the last seven minutes, and when they start the next episode card comes up.

Built on a 21:9 screen

Most films on an ultrawide end up with black bars on all four sides: the bars burned into the file, plus the ones the screen adds. Fill finds the burned-in bars with ffmpeg's cropdetect and scales until the picture meets the edges, without stretching it. Ctrl + scroll zooms by hand, and the choice is remembered per film.

The screenshots on this page open out of letterbox bars as you scroll for the same reason.

Smaller things

Seek previews

Hovering the seek bar shows the frame at that point. The thumbnails are cut from keyframes in one ffmpeg pass the first time a file plays, then cached.

Search as you type

Titles, cast, directors and collections. Typing "mcconaughey" finds Interstellar.

A right-click menu that knows what you clicked

Play from the start, mark as watched, or take something out of Continue watching, with Undo. It comes back on its own if you watch it again.

How seeking works on a stream that's being converted

The usual way to play a file the browser can't decode is to pipe ffmpeg's output into a <video>. That plays, but it can't seek: the browser sees a stream of unknown length that starts at zero, wherever in the film it actually starts.

Flick asks ffprobe for the keyframe just before the point you picked, starts ffmpeg there, and appends the fragments to a Media Source buffer that has been moved to that same point in the film. The video element's clock is then the film's clock, so jumping inside what's buffered is instant and jumping outside it starts a new stream in about a second and a half.

Run it

You need Windows, Node 24, and an ffmpeg build that includes Chromaprint (the full build from gyan.dev does). The first launch asks for your media folder and a free TMDB key.

git clone https://github.com/shreywy/flick
cd flick
npm install
npm start
